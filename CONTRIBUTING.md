# Contribuir sin exponer clientes

Las mejoras son voluntarias. Revisa `USO_Y_LICENCIA.md`, `SECURITY.md` y el flujo de cambios antes de aportar.

1. Usa un ejemplo ficticio; no pegues consultas, expedientes ni salidas de IA con datos identificables.
2. Explica el fallo, fuente, alcance y prueba de regresión. Distingue corrección editorial, técnica y jurídica.
3. Declara que tienes derechos o permiso suficiente sobre el material aportado y señala su procedencia, dependencias y eventual asistencia de IA. No atribuyas autoría humana exclusiva que no puedas sostener.
4. Las contribuciones intencionales se reciben bajo Apache-2.0, sección 5, salvo indicación expresa en contrario; una condición incompatible requiere revisión antes de incorporarse. No se exige transferir toda la titularidad.
5. Trabaja en una rama y abre un PR. Ejecuta tests y empaquetado. Registra las pruebas realmente realizadas. Los cambios jurídicos requieren aprobación profesional identificada; CI no la reemplaza.
6. Cambia `PUBLIC_FILES.json` sólo para archivos públicos revisados. Nunca para incluir expedientes o secretos. Conserva LICENSE y NOTICE en todas las distribuciones.

Las decisiones sobre el repositorio no modifican por sí mismas los expedientes de usuarios ni las copias instaladas. No se ofrece un plazo de atención o aceptación automática de aportaciones. Para incidentes sensibles, no uses incidencias públicas ni reproduzcas el dato.
